# V1 API / bounded execution — P00 review candidate

Status: NOT_ACCEPTED / NOT_IMPLEMENTED. `scripts/p00_build_contracts.py` is the authoring owner of generated OpenAPI DTOs. Generated JSON is reviewable output; never hand-edit it. These new wire DTOs project accepted domain models, not replace their constructors, identities or authority. Missing adapter qualification remains a release blocker.

## Two surfaces, one domain owner

`contracts/python.openapi.v1.json` describes private Python endpoints authenticated by a mounted service credential. `contracts/bff.openapi.v1.json` describes browser mediation authenticated by ASP.NET Identity secure cookie plus mandatory CSRF on mutation. Neither credential is an alternative to the other on the same listener. Python is private-network-only; BFF supplies actor identity after authentication and strips all browser-supplied actor/role/service headers. Python accepts actor context only from that authenticated BFF identity. Single local operator only; no public signup or cross-user delegation in V1.

BFF auth lifecycle uses ASP.NET Identity, local operator bootstrap and same-origin antiforgery. Exact /auth routes are included only in BFF OpenAPI; V1_GENESIS_AUTH_CONTRACT.md owns their lifecycle semantics. Session idle timeout 30 minutes, absolute lifetime 8 hours; logout invalidates the session. Session/signing key storage persists across clean restart and is excluded from logs. Failed login limit 5 attempts in 15 minutes per account; local recovery requires an explicit operator CLI action, not a hidden default password. Secret rotation requires service restart and must not lose durable command receipts.

Default public binding is HTTPS localhost:7443, with exact same origin and no permissive CORS. Host certificate provisioning is explicit installation work; never disable certificate verification to pass J1. Internal network access alone is not authentication. Status/readiness endpoints contain no credentials, native stack or filesystem paths. Backend role checks apply even if UI hides a button.

## Command linearization and retry

Every POST requires Idempotency-Key. Existing-resource mutations also require a quoted integer If-Match; no wildcard. Request fingerprint binds canonical validated body plus original expected revision. Scope is `(operator_id, operationId, resource_id)`; for create, resource scope is that collection. First durable acceptance atomically saves original receipt with domain operation. Exact replay returns original receipt before checking current revision; changed body/revision with same key is 409. Authentication and resource permission are checked on every replay. Failed validation does not consume a key. Concurrent identical valid requests produce one receipt/effect.

Transport timeout: retry the identical command or query the known command ID. No response means unknown acceptance, not failure. Do not generate a new key on retry. Returned operation reference is authoritative for progress. Response receipt gives resource revision at acceptance, not current state. GET returns current revision in body; If-Match uses that value.

Research cancel succeeds only if the command wins the operation row CAS before publication. Cancel-first prohibits later success publication; publish-first remains SUCCEEDED and returns ALREADY_TERMINAL on a fresh cancel command. Replay of an earlier receipt remains that earlier receipt. A stale new cancel command returns 409. A lost lease prohibits both result publication and operation mutation. Cancel-requested infrastructure failure may terminate FAILED, with original cancellation receipt retained.

Simulation create reserves new synthetic account/session identity and returns an async genesis operation. Session becomes CREATED only after successful genesis; failed genesis retains operation evidence and cannot be started. It is never legal to infer account FLAT from failed or missing genesis. START accepts CREATED/PAUSED; PAUSED must re-warm and revalidate. RECOVER accepts HALTED/RECOVERING and ends PAUSED or HALTED, not RUNNING. STOP accepts CREATED/STARTING/RUNNING/PAUSING/PAUSED/RECOVERING/HALTED, blocks new decisions then drains/checkpoints. KILL is allowed for any existing non-STOPPED session, sets a durable risk-increase prohibition and cancels risk-increasing pending orders under fixed policy. KILL is orthogonal to lifecycle; it does not silently flatten. Explicit START clears kill only from PAUSED after full readiness and an audited operator request. FORCE_FLAT requires current known position, matching account revision and risk-reduction permission; accepted canonical execution still governs fills. A session already STOPPED is immutable and cannot FORCE_FLAT; operator must recover a new explicitly linked session/account controller through a separately specified future workflow, not duplicate genesis.

Operation cancellation accepts RESEARCH, DATASET_IMPORT and SIMULATION_GENESIS; rejects SIMULATION_COMMAND with 422 INVALID_INPUT because session commands own those transitions. Genesis reservation/atomic publication rules are in V1_GENESIS_AUTH_CONTRACT.md. Cancellation of a queued research operation directly records CANCELLED. Reading results before successful publication returns 409 READINESS_BLOCKED. Failed run error comes from Operation; no fabricated empty successful result.

## Fixed workload policy v1

These are candidate admission limits, not measured performance claims. `contracts/workload_policy.v1.json` is the machine owner. Changes require a policy version; callers cannot override limits. Missing/invalid config prevents job admission and readiness, never falls back to unbounded execution.

Defaults: one running research worker, at most 20 queued research operations; 1,000,000 bars per dataset consumed by a run; 100 explicit parameter trials; 20 WFO folds × at most 20 candidate configs; 100,000,000 aggregate bar evaluations per parent research request; 1,000 Monte Carlo paths and 100,000 source trade returns; one running simulation session; at most 20 strategies/session; 512 MiB per artifact, 2 GiB published artifacts/run; 4 GiB worker RSS; 30 minutes wall time/research attempt. Admission checks projected aggregate work before any child dispatch. Runtime byte/memory/time limits are also enforced because projections may be inaccurate. Exhaustion records FAILED with workload-limit evidence; it must not publish partial results as success.

Research lease 60 seconds, heartbeat 15 seconds; worker must cease publish attempts after expiry. DB clock decides lease validity. Retry at most two additional attempts for transient infrastructure faults, delays 5 and 30 seconds. Deterministic validation/engine errors and exhausted workload are not automatically retried. API mutation body maximum 1 MiB. Poll operations every 2 seconds while active, backoff to 10 seconds after 60 seconds unchanged; 429/503 honor Retry-After, cap client retries at 5 then show recoverable connection state.

Performance *targets*, measured on fixed release manifest: p95 non-compute API response ≤500 ms under 5 requests/sec; interactive initial workspace ≤3 seconds after authenticated load with local cached static assets; operation cancellation reaches safe checkpoint within 10 seconds for approved fixture workloads. These are release tests, not promises of current throughput. Actual reference host: ≥4 logical CPU, ≥16 GiB RAM, SSD with ≥20 GiB free, supported Linux-container runtime on Windows; report exact CPU/RAM/images/dataset. Do not downgrade correctness when a target fails; profile or explicitly amend scope/target with review.

## Research semantic predicates (beyond JSON Schema)

- Resolve every EvidenceRef by owner/identity/version/hash; mismatch rejects, no latest-version fallback. Config refs resolve registered config schemas; no arbitrary executable class/import expressions.
- Wire timestamps are the RFC3339 UTC-Z subset with 0–6 fractional digits; hour 00–23, valid Gregorian date and seconds 00–59. Offset input, leap seconds and higher precision are rejected rather than silently normalized/truncated; source evidence may retain original timestamp outside this wire DTO.
- initial_capital >0. All price/money decimal strings use normalized fixed-point, no exponent/negative zero/trailing fractional zero. Canonical zero is `0`; do not accept float as money.
- Dataset version is accepted, quality-qualified, immutable; coverage and bar limits checked. All bindings must refer to compatible calendar/contract and timeframe.
- OOS: training interval is dataset start inclusive to training_end exclusive; test_start ≥ training_end and test_end > test_start, within dataset coverage. Training chooses/calibrates only there; test receives frozen parameters, with past-only warmup and no test-data training.
- WFO: calendar sessions, expanding training anchored at dataset start; first training_sessions, then test_sessions, next fold advances step_sessions. Require step_sessions ≥ test_sessions to prevent duplicated aggregate OOS returns. Complete folds only; stop at max_folds or dataset end. Candidate selection maximizes training net return; tie uses config evidence identity lexicographic; test never selects config. No complete fold => INVALID_INPUT.
- Parameter study runs exactly the explicit config references, one run/config, stable config-identity ordering; no hidden search space expansion.
- Monte Carlo uses immutable published BACKTEST trade-return artifact, matching bound source run; independent with-replacement bootstrap of original number of returns per path. It does not simulate fills or create account evidence. PCG64 algorithm, pinned numerical dependency version and seed are recorded; path index determines stable substream, independent of worker order. ≤100,000,000 sampled returns total.
- Comparison is client-selected published result references; no implicit rerun. Metrics with undefined denominator are null plus a defined reason. No Infinity/NaN.

## Queries, errors and audit

List endpoints sort by stable identity ascending, use signed opaque cursor binding actor, endpoint, filter and immutable snapshot. Snapshot TTL 15 minutes; expired/changed binding =>409 REVISION_CONFLICT, caller explicitly refreshes first page. Malformed cursor=>400; no offset-based skip/duplicate. Audit view merges producer snapshots, sorts `(recorded_at,producer,audit_id)` for display only; this order never proves causality. Restrict returned events to operator permission; preserve producer/causation identities.

Result summary is bounded metrics + artifact manifests. Artifact rows use stable row_index order and the same cursor rules; columns and cell count/kinds must agree, UNKNOWN cells carry reason. Cap serialized page at 8 MiB and advance cursor after the last included row. A single unrepresentable row fails the artifact publication gate, not silent truncation. Download accepts only a published artifact ID, rechecks access and hash, streams an attachment with nosniff; no caller path/URL, Range or HTML rendering. Relative manifest URI is never a public browser URL.

Dataset import is multipart metadata(application/json) + file(text/csv), UTF-8 without BOM, RFC4180 header exactly `instrument_id,contract_id,timeframe,bar_open_utc,open,high,low,close,volume`. Timestamp is UTC Z, prices canonical decimals, volume nonnegative integer; high >= max(open,close), low <= min(open,close), high >= low. Caller supplies trusted reference revisions, not executable mappings. BFF/Python stream into staging with a 256 MiB file cap and independently verified SHA256; filename is ignored. One MiB ordinary JSON limit applies to metadata/other mutations, not the streamed file. No remote URL fetch or filesystem path import. Admission creates durable import operation only after complete verified upload; crash before acceptance leaves unreferenced staging file, cleaned after 7 days. Exact retry compares metadata + file hash; file byte differences with same key reject. Successful import atomically publishes qualified DatasetVersion/manifest; cancellation before publish retains no visible dataset. Parent/correction reason must both be present or both absent; a correction must reference the same dataset. CSV cannot directly establish canonical operational observation acceptance; the accepted adapter still validates reference/identity/provenance.

Config registration accepts at most 100 named scalar parameters; duplicate names reject, unknown/missing parameters reject against the referenced registered strategy schema. DECIMAL stays Decimal/string, never float; INTEGER/BOOLEAN/TEXT retain type. V1 strategies requiring nested configs are out of the first registry qualification scope until a versioned contract extends this representation. Accepted config content fingerprint returns the existing immutable version on equivalent registration, with a receipt for the new legal command. Existing sessions are never hot-swapped. Configuration catalog exposes installed, reviewed policy/scenario/calendar/mapping references; these policies are operator-installed versioned files with startup validation, not UI code editors. Catalog caps are admission limits for installed configurations; over-limit startup errors instead of silently dropping entries.

Reconciliation resolve appends a new case version with a mandatory resolution_note through the accepted case transition; it does not alter positions, acknowledge unknown broker outcomes or grant readiness. Current case policy must permit operator resolution; otherwise 403/409. Already resolved with a different new command is 409; exact replay returns original receipt. A resolved case is never a substitute for missing RecoveryCut evidence.

HTTP 413 body/file byte limit; 400 malformed syntax; 401 unauthenticated; 403 permission/mode; 404 missing permitted identity; 409 CAS/idempotency/readiness conflict; 422 semantic/quality/workload validation; 429 API throttling; 503 transient dependency unavailable; 500 unexpected fault with sanitized correlation. Error.retryable is advisory: mutation safety still requires same key. Responses and access logs redact secrets. Durable command/economic audit is atomic with its owning transaction; unsuccessful admission audit must not create a fake accepted command.

## Validation boundary

Schema validation proves payload shape, not DB currentness, actual broker capability, causal provenance or economic correctness. P00 tests cover closed payloads, required identity, money lexical form, mode denial, unknown observation and generated-contract drift. P01–P12 must implement and independently validate the listed predicates and state/concurrency fixtures against actual adapters. Candidate APIs do not grant runtime trading authority.
