**分析。** `allowed_producer_operations` 明確只允許 API top-level result；新的 `allowed_internal_producers` 逐一列出 operation、phase、input draft type、output type、identity rule 與前置條件。`REGISTRY_WRITER` 字串本身不授權任何階段。`REGISTRY_PINNED_SOURCE_IMPORT_V6`、`REGISTRY_GIT_REBUILD_IMPORT_V6`、`REGISTRY_CLOSED_EXPORT_V6` 是原 writer 的具名 adapters，保留所有 supplied permanent IDs／revisions／原 hash domains，不使用 allocator，不提供新 API，也不升級來源 authority。

`RegistryCrossChapterContractSourceRowV6` 封閉實際 `/contracts/{i}` 的 20 個 flat fields；`RegistryGraphScopeSourceRowV6` 封閉原 graph scope payload。必要 schema／catalog／source manifest／source snapshot／B3 與完整 SOURCE bytes 經 `RegistrySourceFileBodyV6` 的有限 resolver profiles：固定 profile → exact original subject → capture artifact／receipt → raw bytes hash／size → literal selector → pinned closed source schema → selected bytes → typed readback。沒有 request filepath／URL／arbitrary JSON／通用 runtime class。每個 JSON schema 的 `const` 是該來源版本的完整有限正文，任何少欄、多欄或不同值均拒絕；來源版本改變必須新增 profile／schema revision。原 domain semantic hash、原始 whole-file bytes hash、selected row bytes hash 與 typed model hash分開驗證。

固定 V5 profiles 僅為 predecessor input witness，portable `source_base` 明定為 `prior_candidate/MA-ARCH-REVIEW-v5-CYCLE01`；不得指向已改寫的 current P6。真正 current6 profiles 必須由最後整合的 P6 refs／bytes 重建。Graph scopes、body schema／catalog support 與 source-snapshot payload 先凍結成獨立 immutable source-row export；resolver 不再把包含 UnitPlans 的整本 GIT registry raw hash 當其 capture 來源。原 registry locator 僅保留 exact subject、原 source hash domain、literal selector 的 provenance。Body catalog 只包含有限型別與穩定 profile-ID enum；literal parser schema／resolver hash 不反向塞入被取樣的 catalog／support payload。唯一原 registry writer 負責這些 identity-preserving source-row exports，沒有增加 truth owner。

`CodeAllocationDraftV5` 的候選 6 input schema 將必填 `allocated_entity_id` 改為 `allocated_target: BodyRefInputV5`；EXISTING_EXACT 只指 exact RegistryEntity，LOCAL_DRAFT 只指同 command 的 RegistryEntityDraft slot。Server 先固定 command／hash／slot mapping，再解析 target 與 initial revision，要求兩者指向同一永久 entity，最後產生原 `CodeAllocation.allocated_entity_id`。原 final CodeAllocation、semantic key 與永久保留／tombstone 原則均不變。`CodeAllocationRetirementDraftV5` 同理使用 `entity_target`；CodeAssignment／LegacyAlias validity 使用 `RegistryCodeValidityDraftV6` 解析 prepared candidate snapshot，避免客戶端預測 snapshot UUID。

同類 FK 檢查另明定 RegistryEntityRevision slot 必須沿用 resolved entity ID，只配置其 fresh revision ID。Project、catalog、format policy、source、scope 與 authority refs 必須是客戶端已讀取且已獲 scope grant 的既有 exact refs；不得 LOCAL_DRAFT 建立新授權。原 source-row `entity_id`／`revision_id` 是原文 provenance，不是新 server ID。原文 import 保留這些 IDs，不得 CREATE 重複 historical permanent identity。新 generic draft 使用有限 `RegistryCandidateSemanticRecordV6`，僅 title／rationale／proposed kind／既有 source與context refs／acceptance_effect=NONE，不含客戶端尚未知的 server IDs。其 kind 只允許 FEATURE、REQUIREMENT、DELIVERABLE、TASK、GAP、CONTRACT。

**替代方案。** 完整展開所有 schema／catalog／manifest 文件為通用 JSON grammar 會引入不必要的第二型別引擎；本案採具名 flat row 加有限 immutable source-file resolver。將配號移到第二個 command 無法滿足既有 same-batch closure；本案採先 prepared mapping 再 original final projection。兩種替代均未用來改變既有 authority 或 allocation 语義。

**風險與限度。** 來源 absence／corrupt／unknown permission 仍是 MISSING／UNVERIFIABLE 或 error；沒有 bytes 時不能以 hash／manifest 當完整正文。固定 V5 input 可核對 6 個 source locators 之外的 bytes；6 個缺失不補造。B3 原 entity/revision 尚無原 identity registry membership，current6 必須保留該既有 ID 並加入 required relevant closure，否則 PARTIAL。Fixture capture/index/grant facts 是作者 logical world 的 stipulated facts，沒有實際 SQL、captured product receipts、restore、broker、migration 或 live 證明。作者 14 個正反例與 typed readback shape 檢核不等於獨立 re-review。
